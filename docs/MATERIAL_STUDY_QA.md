# Проверка блока материалов — 17.10.2026

## Локально подтверждено

- Два Node-теста: подготовка ограниченного описания для заявки без выдуманных размеров/расхода; целостность, происхождение, формат, размеры и отсутствие EXIF у девяти файлов трёх иллюстраций.
- Браузерная проверка настоящего Next.js 16 / React 19 блока вместе со штатной React-формой. Использовалась временная страница с синтетическими CMS-объектами и отключённой отправкой; после проверки страница и публичные тестовые файлы удалены. Подключение к базе не подменялось тестовой базой владельца.
- Та же проверка статической версии: ширины 360/390/768/1440 px, отсутствие горизонтального переполнения, загрузка первого кадра, отсутствие предварительных запросов warm/detail, переключение света и фактуры, управление сборкой клавишей End, выбор слоёв, native dialog/Escape/возврат фокуса, передача выбранного описания, сохранение своего текста, возврат со второго шага формы, reduced motion. Нет ошибок JavaScript и отправки POST.
- Регрессионный тест текущего статического сайта: доступные страницы и локальные ресурсы, меню/клавиатура, два шага формы, сохранение введённых полей, копирование ссылок на идеи, контакты, яхты, прежний партнёрский адрес, 404 у серверных/закрытых маршрутов. Запросов к сторонним origin нет.
- Проверены изображения блока на desktop и мобильном скриншотах. Шрифты и цвета совпадают с текущим сайтом.
- Production build, TypeScript, ESLint и `git diff --check` проверяются перед передачей изменений; итоговый статус сборки также виден в PR/Actions.

## Замечания, исправленные при проверке

React не может гидратировать содержимое HTML template как обычных детей: кадры теперь сериализуются в инертный template из фиксированного набора экранированных атрибутов. Пользовательский HTML не принимается. Отдельно исправлены доступное имя выбора слоёв, возврат к форме при уже заполненном описании и выбор достаточно крупного изображения в окне увеличения. Регрессионный тест меню привязан к конкретному диалогу, поскольку на странице теперь два диалога.

Это функциональная проверка в Chromium, не замер полевых Core Web Vitals и не испытание на физических телефонах. LCP/INP/CLS для реальных посетителей не объявляются измеренными. Контрольные значения проекта сохраняются; их нужно проверять после размещения серверной версии с настоящими CMS-медиа и реальной сетью.

## CMS

В CI добавлен отдельный шаг `Validate material study in a separate acceptance database`: копия исключительно синтетической базы `afara_ci_acceptance`, отдельная `afara_material_study_acceptance`, отдельные медиа и приватные снимки в /tmp. Он проверяет реальную публикацию через Payload/PostgreSQL, обработку трёх медиа, отсутствие source в анонимном чтении, сохранение прежних секций, повторный запуск и сохранение черновика владельца. Тест имеет проверку имени базы до записи. Его результат подтверждается статусом соответствующего шага GitHub Actions; это не применение к рабочей CMS.

В этой среде нет подключения к текущей CMS владельца. `content:material-study -- --apply` **не запускался**. Подготовлены команда, проверка хешей, JSON-снимок перед записью, транзакция и пропуск существующих блоков/черновиков; интеграционное применение к действующей БД здесь не подтверждено. Публичное обновление дизайна не меняет этот статус. Порядок применения — [APPLY_MATERIAL_STUDY.md](APPLY_MATERIAL_STUDY.md).

После применения нужно отдельно подтвердить опубликованные страницы, три медиа и два ответа библиотеки в существующей CMS, затем экспортировать свежий снимок по PREVIEW.md. Нельзя заменять этот шаг запуском seed либо новой CMS.
