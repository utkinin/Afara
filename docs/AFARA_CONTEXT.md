# AFARA · контекст для продолжения

Сохранено 22.10.2026. Памятка именно AFARA, не шаблон фактов для других проектов. Датированные результаты нужно сверять перед новой работой; этот документ не запускает импорт, публикацию или инфраструктуру.

## Подтверждённая концепция

AFARA — текстильный дизайн и инженерная проработка штор для частных и общественных интерьеров. Не ограничивать бизнес только резиденциями и HoReCa.

- Частные интерьеры: дома/резиденции, квартиры, гостиные, спальни, кухни/столовые, детские, домашние кабинеты, ванные с окном.
- Общественные: отели, рестораны, офисы/кабинеты, сцены/зрительные залы, школы/детские сады.
- Отдельное направление: текстиль для частных яхт. Все перечисленные направления подтверждены владельцем.
- Второй свет, эркеры, многослойность, Wave, blackout, моторизация. Высота окон **от 3 до 6 м**, старое «4,5–6 м» не возвращать.
- Изготовление по эскизам и размерам заказчика; консультации по нишам, карнизам и кронштейнам. Не назначать универсальные размеры и характеристики без исходных данных/документов.
- Партнёры: дизайнеры, студии, архитектурные бюро, девелоперы и комплектаторы. White label обсуждается с распределением коммуникации, ответственности, маркировки и прав на публикацию.
- Русская география: **«Базируемся в Санкт-Петербурге. Работаем по всей России. Отправляем изделия в ОАЭ»**. Отправка в ОАЭ подтверждена. Сроки, логистика, таможня и монтаж не обещаются автоматически.
- Для английского направления подготовлена идея международного позиционирования; полноценная EN-версия не считается опубликованной по наличию черновика.

Ценность — помочь согласовать результат и проверить исходные данные, а не просто показать каталог тканей. Концепция задач: завершить интерьер; разобраться с конструкцией; согласовать затемнение; оценить фактуру/цвет. Не медицинские обещания и не психотипы.

Уход за шторами — `/ukhod-za-shtorami/`: оценка, снятие, допустимая обработка, обратная навеска. Для сервиса рассматриваются СПб и Ленобласть, состав/метод/стоимость/сроки подтверждаются по объекту. Не обещать универсальную чистку, сохранение свойств неизвестной ткани, строго два выезда или отсутствие простоя.

## Дизайн и содержание

Сохранять текущую интерьерную композицию, тёплый светлый фон, сливовый акцент, Cormorant Garamond и Manrope; крупная читаемая типографика по PROJECT_PLAYBOOK. Hero растёт с текстом. Основные восемь карточек пространств/композиций/деталей имеют восемь разных изображений; новые соседние иллюстрации должны объяснять содержание.

Фото-концепции не выдавать за реальные работы. Повторяющийся заголовочный бейдж «ИИ-концепция» убран, общее честное пояснение сохранено. Школа и детсад должны выглядеть как соответствующие помещения, не гостиничный интерьер. Реальные кейсы/специалист/отзывы добавляются только по материалам владельца.

Точки входа: пространства, услуги, партнёры, пошив по эскизам, уход, контакты. Услуги не смешивать с типами помещений. Выбор задачи и просмотр ткани помогают заполнить существующее обращение, не отправляют сообщение и не заменяют введённое. Фактура/свет/полнота складки — обсуждение, не измеритель ткани или калькулятор ниши.

Числа исторические, последующие правки владельца приоритетнее. Уход и образовательные изображения перенесены в CMS, повторно применять импорт не требуется.

Публичные телефон/email/реквизиты и юридические документы в проверенной CMS ещё не были заполнены. Подтверждённый Telegram добавлен позже в конфигурации лёгкого запуска; не предполагать, что он синхронно внесён в серверную CMS. Реальные кейсы, портрет и документы не заменять выдумками. Полный серверный консультант: поиск только по опубликованным одобренным материалам, буквальные цитаты со ссылками; модель необязательна. Ключ и реальный платный вызов не проверены. Публичное evidence закрыто. Короткие ссылки — только внутренние опубликованные цели, 302/no-store, отключение/отзыв 404.

Не выполнять seed/reset/schema push на рабочей БД. Шесть миграций и baseline проверены; заполненный dump восстанавливается в **пустую** БД до обычного db:migrate, не поверх существующего наполнения. Отдельно восстанавливается media. Версии и исторические файлы не удалять как мусор.

Приватный актуальный переносной архив этой среды: `/workspace/afara-release-20261021/private/AFARA_CMS_Transfer_2026-10-21.tar.gz`. Backup/manifest/снимки и подтверждение восстановления там же. **Не публиковать эту папку, dump, `.env.local`, заполненные env или ключи.** После запуска production актуальные данные берутся с нового сервера; старый архив не возвращается поверх них.

## Проверки и дальнейшая работа

На 21.10 пройдены lint/typecheck/build, 24 серверных теста, 2 E2E, импорт ухода, проверка услуг и три статических сценария. Восстановление dump, 162 SHA-256 медиа, production HTTP/CSP/закрытие MFA и интерактивное создание владельца проверены отдельно. Результаты не переносить автоматически на новый код/домен. Изменяющие тесты — только изолированные acceptance-БД и media.

Важные исправления не потерять: cache keys JS по содержимому; SMTP не блокирует запуск страниц; outbox/worker сохраняет заявку при сбое; create:admin корректно завершает процесс; повторный импорт не затирает владельца. Лёгкая статика использует собственные проверки и контакт, не имитирует полный сервер.

В облаке использовать существующий checkout, не создавать worktree/клон без необходимости. Хранить `.env.local`, читать только нужные сведения о наличии секретов. Git работает через штатный proxy; не просить токен до проверки доступного доступа. Docker VFS расходует много диска; перед тяжёлой сборкой проверить место, не удалять volumes. Не собирать `.next` одновременно с работающим dev/start в том же каталоге.
