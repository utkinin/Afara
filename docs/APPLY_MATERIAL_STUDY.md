# Добавление блока в существующую CMS

## Условия

Использовать актуальные исходники этой доработки и действующую **development/acceptance** CMS AFARA с прежней базой PostgreSQL и прежним MEDIA_DIR. Не запускать seed, reset, schema push, создание новой базы или bootstrap владельца. Изменений SQL-схемы и миграций для этого блока нет: используется прежняя секция `materials` с якорем `material-study`.

Перед применением сохранить проверенный backup PostgreSQL и файлов медиабиблиотеки обычным способом проекта. JSON-снимок команды содержит страницы, версии, знания и метаданные медиа; он не заменяет полный backup базы и файлов. Директория для него должна быть приватной и находиться вне Git checkout, public и каталога экспортируемого превью.

## План и применение

Переменные DATABASE_URL, PAYLOAD_SECRET и MEDIA_DIR берутся из существующего закрытого окружения; не вставлять их в отчёт или PR.

Сначала проверить план без записи:

```bash
AFARA_STAGE=development AFARA_DB_PUSH=false npm run content:material-study
```

Затем применить к той же проверяемой CMS, указав реальную приватную директорию backup:

```bash
AFARA_STAGE=development AFARA_DB_PUSH=false \
AFARA_CONTENT_BACKUP_DIR=/absolute/private/afara-content-backups \
npm run content:material-study -- --apply
```

Команда проверяет SHA-256 всех девяти файлов; использует транзакцию; создаёт три медиа с производными Payload; добавляет блок в `home` и `poshiv-po-eskizam`; добавляет два отсутствующих ответа библиотеки по цвету и нише; пишет аудит. Опубликованные медиа имеют собственное происхождение, а не статус выполненной работы. Исходные секции не заменяются. Страница с черновиком владельца и уже существующий блок пропускаются. Повторный запуск не перезаписывает ручные правки блока.

Сверить вывод `applied`, `pages`, `report`. Отсутствующую страницу команда не создаёт. При ошибке транзакция откатывает записи БД; файловая система не входит в транзакцию PostgreSQL. После ошибки проверить созданные файлы и убрать только подтверждённые несвязанные остатки по регламенту медиахранилища. Не удалять общую библиотеку.

## Редактирование владельцем

«Страницы» → главная либо «Пошив по эскизам» → секция с якорем `material-study`:

- `heading`, `kicker`, `body` — заголовок и введение.
- Первые три карточки по порядку: нейтральный свет, тёплый свет, фактура. В каждой — своё фото, заголовок переключателя, описание и alt.
- `linkLabel` первой карточки — надпись кнопки к форме.
- `visible` и порядок секций — видимость и место блока.

Не менять служебный якорь при переименовании заголовка. Для блока нужны минимум два опубликованных изображения; если их меньше, он скрывается. Реальные фотографии подменять только после проверки прав, происхождения и соответствия подписи. Сохранить черновик → посмотреть с телефона и desktop → опубликовать администратором. Деплой для изменения содержимого уже установленного блока не требуется.

## Проверка и экспорт

Проверить CMS и публичное приложение: три изображения, переключения, клавиатуру, увеличение, коэффициент, слои, сохранение введённой заявки. Проверить новую опубликованную страницу и доступность двух ответов консультанту. Черновики и приватное поле source не должны быть доступны анонимно.

После применения экспортировать опубликованные страницы по PREVIEW.md. Экспорт теперь сохраняет инертные фото-ресурсы и тот же небольшой контроллер. Команда не включает форму, консультанта или CMS на GitHub Pages: это статический просмотр.
