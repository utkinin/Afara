# AFARA: полезные ответы и измерение интереса

Проверено 17.10.2026. Статья Click.ru на Хабре используется как список гипотез, а не нормативный технический стандарт. Для спорных утверждений проверены первоисточники.

## Что внедрено в код

- Максимальная достигнутая высота страницы с шагом 25%. Дополнительных событий на каждое движение нет: число обновляется вместе с существующим heartbeat / финальным beacon.
- Серверная классификация источника: распознаваемый referrer ИИ-сервиса, отдельно AI-UTM, поиск, платная метка, другое внешнее направление и прямой/непереданный источник. Сравнение визитов со связанными заявками. Нет автоматического объявления Google/Яндекса нейропоиском по недостоверным URL-параметрам.
- 32 редакционных ответа в `content/answer-library.ts`, распределённых по существующим разделам. Служебное поле «Источники и ограничения» в CMS, закрытое от публичного API и консультанта.
- Импорт только новых черновиков, сохранение существующих записей, проверка опубликованной целевой страницы, идемпотентность и транзакция. `--list` работает без БД; обычный запуск — dry-run; `--apply` не публикует.
- Серверная JSON-LD-разметка Organization, WebSite, WebPage/FAQPage, BreadcrumbList и Service для подтверждённых услуг. FAQ совпадает с доступным посетителю текстом, скрытые/неодобренные ответы исключены. Нет вымышленных товаров, цен, отзывов и рейтингов. JSON экранирован и использует nonce текущего запроса.
- Никаких новых зависимостей и клиентского JavaScript для библиотеки/разметки. Полный каталог ответов не отправляется в клиентский аналитический модуль.

## Что не переносится из предложенных промтов

| Идея | Решение |
| --- | --- |
| Ответ строго 50–80 слов якобы обязателен | Нет такого требования Google. Краткость подбирается по вопросу; библиотека не растягивается ради счётчика. |
| JSON-LD гарантирует цитирование / даёт 70% потенциала | Не подтверждено. Разметка нужна для согласованного описания, не как гарантия выдачи. |
| FAQ rich results как способ получить расширенный сниппет | Google прекратил показывать их с 07.05.2026. FAQPage остаётся типом Schema.org, но не обещанием такого сниппета. |
| FID и FCP как Core Web Vitals | Текущие CWV: LCP, INP, CLS. FCP — дополнительная метрика; FID заменён INP. |
| Любой dimout пропускает фиксированные 10–30% света | Проверять паспорт. У DELIUS, например, есть иные значения; не обобщать их на ассортимент AFARA. |
| Ниша 15–16 см всегда подходит для двух рядов | Не использовать. В документах систем размеры зависят от верха, шага и комбинации рядов. |
| Слово blackout означает один состав и один режим стирки | Не использовать. Проверяется конкретная ткань и готовое изделие. |
| 75% прокрутки = прочитал / дошёл до цены | Нет. Это достигнутая доля высоты с учётом viewport. Положение блока и чтение из неё не следуют. |
| Referrer показывает все AI-упоминания | Нет. Только наблюдаемые переходы; отсутствие referrer не означает отсутствие ИИ. |
| Автозахват контактов из любых форм | Не добавлять. Только принятая заявка и отдельное необязательное разрешение на связь с историей. |
| Собственные карты координат, запись экрана и движений | Не добавлять в эту версию. Нет необходимости для базового отчёта; внешний replay также не включать автоматически. |
| «Schema.org 2.0», `light_transmition`, `fabric_brand`, `washable` как готовые свойства | Не добавлять вымышленные свойства. Реальные подтверждённые характеристики — через допустимые поля и PropertyValue, когда появится реальный каталог. |
| Открыть только специальным AI-ботам всё, включая служебные пути | Сохранить общий запрет /admin, /api, /preview и серверные права. Robots.txt не защита данных и не гарантия индексации. |

## Как наполнять без лишнего

1. Прочитать [32 ответа в удобном формате](ANSWER_LIBRARY.md). `npm run content:answers -- --list` выводит тот же набор в JSON без подключения CMS, SMTP или базы. Для последующего импорта нужны backup и миграция.
2. В существующей CMS с `AFARA_STAGE=development`, `AFARA_DB_PUSH=false` и настроенным DATABASE_URL выполнить `npm run content:answers`: это только план. Для создания новых черновиков — `npm run content:answers -- --apply`, указав приватную `AFARA_CONTENT_BACKUP_DIR` вне checkout.
3. Если целевой страницы нет или она не опубликована, запись пропускается. Не создавать пустой SEO-раздел ради ответа.
4. В «Публичной базе знаний» открыть черновик, прочитать служебные источники, уточнить применимость. Проверить, что текст не обещает отсутствующий товар/услугу. Одобрить и опубликовать от ADMIN.
5. Ответ появится на связанной странице и в базе консультанта штатным путём. Не публиковать все 32 на главной и не создавать под них 32 тонкие страницы.
6. Для дополнения использовать [CONTENT_AI_PROMPT.md](CONTENT_AI_PROMPT.md). Новые сведения о товаре требуют его документации; статья о бренде её не заменяет.

## Что оставить следующим небольшим этапом

Проверка домена в Google Search Console и Яндекс Вебмастере — после получения доступа владельца. Подключение их статистики требует реальных разрешений; таблица с выдуманными запросами недопустима. В актуальной справке Google есть Generative AI performance report; доступность и охват надо проверить для конкретного ресурса. Это не склейка запроса с персональной историей браузера.

Полевые LCP/INP/CLS по странице и типу устройства — отдельная, явно настроенная RUM-интеграция с выборкой и размером наблюдений. В текущей доработке не добавляется самодельный PerformanceObserver, выдающий неполный замер за Core Web Vitals. PageSpeed/Lighthouse — лабораторный замер, а не p75 реальных посетителей. Пороговые ориентиры «хорошо»: LCP ≤2,5 с, INP ≤200 мс, CLS ≤0,1 на p75. Результаты и причины отклонения важнее обещания FCP как причины цитирования.
