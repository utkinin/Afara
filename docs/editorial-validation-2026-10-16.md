# AFARA — применение нового редакционного пакета

16 октября 2026, Москва. Пакет разработан заново по `EDITORIAL_RESEARCH.md` после явного подтверждения владельца. Исходный сторонний архив не получен. Предварительное ограничение из `editorial-package-check-2026-10-16.md` снято созданием нового пакета; прежний отчёт описывает более раннюю проверку.

## Реализовано и применено

- 16 самостоятельных оригинальных генераций: общая композиция, 14 пространств и фактуры. Добавлены 16 мобильных кадров 768×1024, явно обозначенных как производные, а не отдельные генерации. WebP, хеши, дата, идентификаторы результатов и промпты находятся в `fixtures/editorial/manifest.json`. Изображения производителей не скачивались.
- Новая галерея с содержательными вопросами, обозначением концепций и постоянными якорями. «Сохранить идею» копирует URL текущей композиции, сохраняя префикс размещения; при запрете буфера доступно поле для ручного копирования. Концепции не становятся реальными кейсами.
- Кнопка переписки использует подтверждённый Telegram из CMS либо внутреннюю форму. Телефон и Telegram не выдумываются. Локально создаваемый QR контактов сохраняет `/Afara/`, скрывается при неподходящем адресе; фактическая матрица декодирована тестом.
- Консультант переносит вопрос в ещё пустое описание формы по явному нажатию. Уже введённый текст сохраняется. Перенос не отправляет заявку; самостоятельного обучения на сообщениях нет. Сохраняются прежние ограничения одобренной опубликованной базы.
- Восемь самостоятельных редакционных ответов подготовлены как неодобренные черновики. Ссылки производителей взяты из исследования; независимая проверка актуальности карточек, протоколов и сертификатов не заявляется. Сторонний Volvo/Bellton AG явно не приписывается AFARA. Свойства артикула не обобщаются, численные классы акустики не добавлялись.
- Исправлено разрешение изображений в защищённом preview черновиков с проверкой прав текущего редактора. Публичный рендер не получает этот доступ.
- Импортёр `content:visuals`: план без записи, проверка всех файлов до импорта, транзакция, сохранение существующих черновиков, проверка неизменности исходных записей, повтор без дублей. Он не запускается при install/start и не вызывает seed. Новая схема БД не требуется.

В **основную CMS** добавлены 32 медиа-черновика, 15 черновиков страниц и восемь ответов-черновиков. Публичные 18 страниц и 21 одобренный ответ сохранены. Всего теперь 17 ответов-черновиков. Права на новые изображения автоматически не подтверждались. Реальных пользователей и заявок по-прежнему 0.

Полное совпадение исходных страниц, знаний, медиа, существующих черновиков и настроек подтверждено SHA-256 `96044e6a30f0c46c106debdaee741f5dd193dd0c1c352e9ec27f31f526310c96`. Повторное применение не создало новых материалов. До/после сохранены приватные дампы и media вне Git; начальный дамп восстановлен в отдельную acceptance-БД, итоговый проверен через `pg_restore --list`. Ничего из нового содержания не опубликовано автоматически.

## Что остаётся сделать

- ADMIN должен проверить изображения и права, мобильные композиции и новые тексты; опубликовать сначала медиа, затем выбранные страницы. Существующий редакторский черновик, если появился, согласуется отдельно. Восемь ответов требуют отдельного одобрения для консультанта.
- Нужны настоящие Telegram/контакты, юридические документы, реальные кейсы, фотографии и сведения о специалистах. Новые концепции не подтверждают выполненные работы или сертификаты.
- Ключ и явное включение ИИ, приёмка реального провайдера; в этой работе платные вызовы модели не выполнялись. Без ключа работает поиск цитат.
- Для серверных функций нужен Node-хостинг. GitHub Pages показывает только опубликованный статический снимок; черновики, API, консультант и отправка заявок в него не включаются.
- Новый Docker-образ этого пакета не собирался. Проверена production-сборка Node; прежний локальный Docker-образ относится к предыдущему коду. Настоящие MFA, SMTP-доставляемость, внешний backup/restore и целевой хостинг не проверялись.
- Прежний бюджет первоначального JS остаётся открытой задачей: оптимизация до 200 KiB этим пакетом не выполнена. Новые полевые показатели производительности не заявляются.
