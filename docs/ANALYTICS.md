# Аналитика AFARA

Модуль использует существующие Next.js, Payload и PostgreSQL. ClickHouse, Prisma, сторонний счётчик, сервис поиска контактов и запись экрана не добавлены. Новых npm-зависимостей нет.

## Что увидит владелец

После входа ADMIN в меню появляется «Аналитика», адрес `/admin/analytics`.

- Период 7/30/90 дней, фильтры источника и связи с заявкой.
- Визиты, браузеры, визиты со связанной заявкой и недавняя активность.
- Источники/кампании, страницы входа, переданные запросы и UTM-метки, популярные страницы и среднее активное время.
- Последние 50 визитов; открытие визита показывает до 250 шагов и до 20 визитов этого браузера.
- Контакты берутся из заявок только при отдельном согласии на связь с историей. В событии email/телефон не дублируются. Связь означает историю браузера, не доказанную идентичность человека.
- ADMIN может удалить историю выбранного браузера. Заявки и контакты при этом сохраняются, ссылки на историю обнуляются. Отдельное доказательство ранее полученного согласия остаётся в заявке.

Редактор EDITOR и анонимный посетитель отчёт и коллекции аналитики не читают. В production сохраняется прежний обязательный MFA-шлюз. Исключения в middleware касаются только POST `/api/analytics/consent` и POST `/api/analytics/track`; это не публичные методы чтения.

## Поведение посетителя

До согласия нет идентификатора аналитики, sessionStorage аналитики и запросов сбора. Кнопки разрешения и отказа доступны одинаково; отказ не закрывает сайт и не мешает заявке. Кнопка «Закрыть» также не считается согласием. Повторно открыть выбор можно в footer через «Настройки cookie».

После разрешения сервер создаёт случайный идентификатор в подписанной HttpOnly first-party cookie. JavaScript его не читает. Срок — максимум 90 дней с момента разрешения, без бесконечного продления. Отдельная необходимая cookie хранит только сам выбор и публичную версию условий; отказ также запоминается. SessionStorage после разрешения содержит только случайный ключ текущего визита и время активности.

Трекер подключается динамически только после согласия. Он записывает публичный путь без query/hash, разрешённые UTM, внешний hostname источника, приблизительные устройство/браузер/ОС и разрешённые действия связи. Полный referrer, URL с контактами, все cookie, значения полей, нажатые клавиши, координаты, экран и отпечаток устройства не отправляются.

Сигнал времени — раз в 20 секунд, только при накоплении активности. Учитывается видимая вкладка в фокусе с действием за последние 60 секунд. При уходе отправляется небольшой beacon; heartbeat обновляет накопленное время одной записи, а не создаёт новые строки. Сервер ограничивает время реально прошедшим интервалом и принимает повторные сигналы монотонно. Визит завершается после 30 минут без активности. Метрика приблизительная: закрытие приложения, блокировщики, потеря сети и особенности фокуса браузера снижают полноту.

Сбор учитывает DNT/GPC. Отзыв останавливает трекер и транзакционно удаляет историю текущего браузера. Подписанный идентификатор не может воссоздать удалённую запись поздним beacon. При сетевой ошибке отказ сохраняется локально; интерфейс сообщает, что удаление на сервере ещё не подтверждено, и предлагает повторить отказ.

## Контакты и связь с заявкой

Автоматического перехвата всех `<form>` нет. На втором шаге штатной заявки появляется отдельная **необязательная**, изначально пустая галочка: разрешить связать заявку с историей этого браузера за 90 дней. Она доступна только при действующем разрешении аналитики. Разрешение обработки заявки остаётся отдельным.

При успешной отправке сервер проверяет подписанную cookie, актуальную версию опубликованных условий и принадлежность просмотра этому браузеру. Заявка, ссылка на визит/браузер и доказательство отдельного согласия сохраняются одной записью вместе с прежним outbox. Чужой view ID, несовпадающая версия, отсутствие согласия или сбой аналитики не должны помешать обычной заявке. Идемпотентность заявки определяется её основными полями, а не меняющимся идентификатором просмотра. Повторный запрос не создаёт дубликат.

## Что нельзя достоверно получить

- Чужие cookie, почту и телефон без передачи самим посетителем.
- Большинство органических запросов Google/Яндекса для отдельного визита. Используются только фактически переданный параметр известного поискового источника либо `utm_term`; рекламная метка подписана отдельно. Агрегированный импорт Search Console / Вебмастера не подключён.
- Всех посетителей и все переходы: отчёт ограничен согласием, возможностями браузера и сроком хранения.
- Точный город по IP. Город берётся из заявки. Страна опциональна при доверенном прокси.
- Выручку: AFARA принимает заявки, а фактов оплаты в модели нет.

Контактоподобные значения в UTM и запросах отбрасываются. В частности, длинная числовая метка может быть исключена как похожая на телефон. Для кампаний предпочтительны читаемые имена, например `architects_autumn`, без персональных данных.

## Хранение и обслуживание

Три закрытые коллекции: `analytics-visitors`, `analytics-sessions`, `analytics-events`. Индексы покрывают ключи, связи и даты. Сырые IP и полный User-Agent в них не записываются. Для защиты от перегрузки есть краткоживущие rate-limit записи. Если явно настроен доверенный Cloudflare, IP используется только для суточного HMAC ключа такого защитного лимита, без сохранения исходного адреса. Это псевдонимизация, не обещание юридической анонимности.

Существующий worker уведомлений ежечасно удаляет истёкшие записи аналитики. Просроченные данные сразу исключаются из отчёта и приёма событий. Worker должен работать постоянно. У hosting/CDN могут быть собственные журналы: их параметры, сроки и исключение cookie/тел/почты из логов настраиваются отдельно; модуль не меняет чужие access logs.

## Включение в действующей CMS

1. На сервере с исходниками этой версии сохранить проверенный backup PostgreSQL. Не запускать seed/reset/schema push и не заменять существующие тексты.
2. До старта нового приложения выполнить штатную `npm run db:migrate` с существующим закрытым окружением и `AFARA_DB_PUSH=false`. Новая миграция — `20261017_203641_analytics`; она добавляет таблицы и поля, оставляя аналитику выключенной. Snapshot и типы сгенерированы текущим Payload.
3. Опубликовать актуальные документы типов `privacy` и `analytics`, описывающие фактическую обработку, оператора, хранение и отдельную добровольную связь с заявкой. Юридические документы автоматически не создаются и не публикуются.
4. В «Сайт и контакты» → «Аналитика» ADMIN включает флаг и публикует настройки. Без флага и обоих опубликованных документов сбор не работает.
5. Перезапустить приложение и worker; проверить отказ/разрешение, заявку с пустой и отмеченной отдельной галочкой, отзыв и закрытый отчёт. Для обычной редактуры разрешение по-прежнему не нужно менять в коде.

`ANALYTICS_TRUST_CLOUDFLARE=true` допустим только при закрытом прямом доступе к origin, когда Cloudflare достоверно устанавливает и перезаписывает `cf-connecting-ip`/`cf-ipcountry`. По умолчанию заголовки игнорируются. При выключенном режиме страна неизвестна, raw IP для аналитики не используется. Новых секретов модулю не нужно; применяется действующий PAYLOAD_SECRET с отдельным назначением подписи.

Автоматический `migrate:down` этой миграции остановлен: он удалил бы историю и доказательства согласия. Для отключения достаточно флага Site. Возврат схемы требует отдельно проверенного backup/плана; молчаливого удаления данных нет.

На GitHub Pages модуль не собирает данные: это прежний статический просмотр без CMS/API. Генератор preview удаляет серверные элементы согласия и связи с заявкой. Наличие файлов в main не доказывает применения миграции или включения сбора в рабочем окружении.

## Первичные источники

- [MDN: Document.cookie](https://developer.mozilla.org/en-US/docs/Web/API/Document/cookie) — доступ к cookie и HttpOnly.
- [Google Search Console: Performance report](https://support.google.com/webmasters/answer/7576553?hl=en) — данные поисковых запросов и ограничения отчёта.
- [CNIL: Identify personal data](https://www.cnil.fr/fr/node/698) — псевдонимизация и различие с анонимизацией. Cookie-плашка и hash IP сами по себе не гарантируют соблюдение всех применимых правил обработки.
