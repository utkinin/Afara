# AFARA: фотографии, Россия и партнёрство

Это изменения поверх `fe0e9b9728e91f7c5131132ed7296f01bba727ab`. Не применять старый архив и не запускать seed поверх существующей CMS.

## Что уже подготовлено

- Разные иллюстрации в «Пространствах», трёх «Композициях» и трёх карточках «Разбора решения».
- Исправление высоты на «от 3 до 6 м», русской географии на Санкт-Петербург / всю Россию, удаление публичных ИИ-подписей.
- `/partnyoram/`, блок на главной, верхняя / мобильная навигация, footer, SEO, пять ответов для утверждённой библиотеки консультанта.
- Обычная схема Payload без новых таблиц и миграций. Тексты, фото, контакты, FAQ и SEO по-прежнему редактируются через CMS.

## Применение в существующей среде Codex с CMS

1. Сохранить изменения владельца, прочитать AGENTS.md, совместить ветку с актуальным main. Ничего не сбрасывать.
2. Проверить рабочие DATABASE_URL, PAYLOAD_SECRET и MEDIA_DIR, не выводя секреты. Сохранить штатный дамп PostgreSQL и media вне Git; проверить восстановление на acceptance-копии по прежней инструкции проекта.
3. В acceptance-копии выполнить типы, lint, сборку и новый план. План ничего не записывает:

```sh
AFARA_STAGE=development AFARA_DB_PUSH=false npm run content:refresh
```

4. Если опубликованным страницам соответствуют новые черновики владельца, импорт остановится. Сохранить и совместить их, не обходить проверку и не удалять версии. Не затрагивать заявки, пользователей, SMTP и секреты.
5. Для публикации в согласованной существующей CMS:

```sh
AFARA_STAGE=development AFARA_DB_PUSH=false AFARA_CONTENT_BACKUP_DIR=/absolute/private/afara-content-backups npm run content:refresh -- --apply-published
```

Команда проверяет хеши иллюстраций, сохраняет приватную копию контента вне checkout, повторно проверяет исходное состояние и публикует изменения транзакционно. Существующая партнёрская страница не переписывается при повторе. После переноса все новые поля доступны в обычной CMS. Происхождение визуальных концепций сохраняется в закрытом источнике медиа; концепции не становятся выполненными работами.

6. Проверить анонимно `/`, `/partnyoram/`, обе обзорные страницы, контакты, меню на 360/390/768/1440 px. В карточках должны быть разные фото; старая высота, ИИ-подписи и мировая география в русской версии должны отсутствовать. Проверить повтор команды и закрытый доступ к CMS/черновикам. Для FAQ консультанта — только опубликованные одобренные ответы с реальной страницей-источником.
7. Экспортировать новый снимок из реально опубликованной CMS по PREVIEW.md. Статическое превью не подтверждает работу CMS или приём заявок. В отчёте различать обновлённое превью, рабочую CMS и production.

После устранения продолжать с проверкой текущей ветки и плана; повторно не импортировать старые пакеты и не удалять данные. Не заявлять автоматическое возобновление, пока конкретная задача Codex не подтверждена сервисом.
