# Управление AFARA

Блок «Свет · фактура · складка»: в «Страницах» найдите секцию `materials` с якорем `material-study`. Заголовок и введение — поля секции; три карточки — нейтральный свет, тёплый свет и фактура; фото, alt, подпись и название переключателя меняются в карточках. Подпись кнопки берётся из `linkLabel` первой карточки. Сохраните служебный якорь, используйте черновик и предпросмотр перед публикацией. Первичное добавление в существующую базу описано в [инструкции](docs/APPLY_MATERIAL_STUDY.md); код сам не меняет CMS при запуске приложения.

1. На сервере выполните `npm run create:admin`, введите свой email и уникальный пароль в скрытом вводе. Это однократная операция. В production сначала нужен проверенный MFA-шлюз; без него административные пути закрыты. Чужие пароли и ключи не передавайте в чат.
2. Откройте `/admin`. Одна штатная админка Payload на русском. На телефоне боковое меню сворачивается.
3. «Сайт и контакты»: отредактируйте публичные контакты и географию. Почта входа и получатель заявок — другие настройки. Не меняйте их ради изменения email на сайте.
4. «Страницы»: выберите страницу, редактируйте H1, вводный текст, hero и секции. Порядок элементов задаётся массивом. Сначала сохраните черновик. Заголовок страницы не меняет URL. При публикации нового пути прежний адрес получает постоянный HTTP 308 на текущую страницу. Названия и дочерние связи используют ID, поэтому цепочки не накапливаются. Проверьте новый адрес перед публикацией.
5. «Медиабиблиотека»: JPEG/PNG/WebP до 20 МБ и 50 MP, без SVG/HTML/архивов. HEIC напрямую не поддерживается: на iPhone экспортируйте JPEG либо выберите совместимый формат в настройках камеры. Укажите alt, происхождение и основание прав. Не загружайте чужие Pinterest-фото как свои работы. ADMIN подтверждает права и публикует. Новые черновые файлы закрыты по прямой ссылке; опубликованные фото нельзя обещать отозвать из копий посетителей.
6. В редакторе страницы доступен предпросмотр по действующей сессии. Штатные ширины Payload — 1440/768/390. Проверяйте реальный текст, а не миниатюру макета. EDITOR сохраняет черновики, ADMIN публикует. Изменения доступны без деплоя.
7. «Документы»: добавляет и публикует только ADMIN. Нужны утверждённые документы типов privacy и consent. При правке опубликованного текста обновляйте версию. До этого форма не принимает реальные заявки. Сохранённые заявки содержат текст и версию согласия на момент отправки.
8. «Получатели заявок»: ADMIN указывает закрытый email. SMTP задаётся на сервере. Worker должен работать постоянно; локально `npm run worker`. Статусы и ошибки доставки доступны в карточке заявки. Не отправляйте заявку повторно из-за почтового сбоя.
9. «Заявки»: ADMIN меняет статус и внутренние заметки; исходные поля защищены от изменения. CSV доступен авторизованному ADMIN кнопкой в журнале или по `/api/export`, не публично. Есть флажок архивирования. Максимум текущего экспорта — 1000 записей; выгрузки содержат персональные данные и требуют защищённого обращения.
10. История версий — штатная Payload. Перед восстановлением опубликованной версии сделайте резервную копию и проверяйте поведение на тестовой копии; сценарий «восстановить только как черновик» ещё требует доводки и отдельной приёмки.

## Новое направление и частные яхты

Все перечисленные владельцем направления подтверждены. Подготовлены и опубликованы 18 страниц, включая контакты. Яхты — самостоятельная страница без родителя, доступная из «Пространств». Чтобы добавить следующее направление: создайте `direction`, задайте уникальный путь, содержательное введение, разделы и порядок. Для комнаты/объекта выберите обзор-родитель; для самостоятельного направления оставьте родителя пустым. Родитель должен быть опубликован до публикации дочерней страницы. ADMIN отмечает фактическое оказание услуги. Ни редактирование кода, ни новый деплой не нужны. Заполненные прежние тексты не заменяются шаблоном.

## Доверие и контакты

«Сайт и контакты» содержит общий источник каналов связи, географии, режима, встреч и реквизитов. Не используйте email входа вместо публичной почты. Контактная страница, footer и блок формы получают одни и те же опубликованные значения. Мессенджеры: проверенные HTTPS-ссылки Telegram/WhatsApp/MAX/VK. Неподтверждённые каналы и адрес посещения оставьте пустыми.

В `О студии` добавляйте только подтверждённые имя, роль и фотографию специалиста с правом публикации. Сейчас опубликована специализация студии, без придуманного человека. В «Реальные работы» опишите задачу, особенности пространства, решение и добавьте опубликованные фотографии с происхождением «Работа AFARA». Концепция не пройдёт проверку публикации кейса. При отсутствии кейсов публичная галерея скрыта. Не добавляйте стаж, отзывы, сертификаты и гарантии без основания.

Состав работы, согласования, расчёт и FAQ редактируются в содержательных блоках доверия. До изменения условий сверяйте их с реальным предложением и договором. Редакционные варианты не означают автоматически включённый монтаж, фиксированный срок или гарантию.

## Публичная база и консультант

1. В «Публичной базе знаний» создайте вопрос и короткий проверенный ответ. Укажите опубликованную страницу-источник: этот ответ будет показан и на ней.
2. Задайте ключ темы и синонимы. Для одного факта используйте один ключ: разные опубликованные ответы с одним ключом заставят консультанта отказаться от ответа до уточнения.
3. EDITOR сохраняет только черновик. ADMIN проверяет факты, отмечает одобрение и публикует. При изменении содержания проверьте и одобрите новую версию. Девять дополнительных редакционных ответов оставлены черновиками для такой проверки.
4. Проверьте известный вопрос, вопрос без ответа, ссылки и поведение после изменения/снятия источника с публикации. Обычный черновик не меняет прежний опубликованный ответ; снятие с публикации/удаление делает материал недоступным.
5. Включение кнопки — `Сайт и контакты → Консультант`. Без настроенного провайдера работает честно обозначенный поиск с цитатами. Он не выдаётся за генерацию ИИ.
6. Настоящая модель требует серверных `AFARA_AI_API_KEY`, `AFARA_AI_ENABLED=true`, модели и квоты. Ключ не вводится в контент CMS или чат. Перед включением согласуйте передачу вопроса и разрешённых текстов внешнему провайдеру; смотрите DEPLOYMENT.md.

Вопросы не сохраняются в журнал и не создают заявки. Виджет просит не вводить личные данные; явные телефон/email не передаются модели. Отдельная ссылка ведёт к штатной форме, отправка контакта выполняется только явным действием с необходимым согласием. Полностью исключить ошибки модели или семантическую нерелевантность нельзя; итог ограничен проверенными буквальными цитатами, но подбор и полноту ответов нужно контролировать.

## Короткая ссылка

ADMIN открывает «Короткие ссылки», задаёт имя латиницей (например `yahta`), выбирает опубликованную страницу и сохраняет запись включённой. Кнопки «Скопировать»/«Поделиться» используют обычный адрес `/s/yahta`. На устройствах без системного Share доступно копирование. Разрешение буфера обмена зависит от браузера; при отказе показывается адрес для ручного копирования.

Назначение можно изменить без смены короткого имени. Применяется 302 и `no-store`, основной SEO-адрес страницы сохраняется. Отключённая ссылка, снятая с публикации или удалённая цель дают 404. После удаления цели назначение можно выбрать заново. Внешние сайты, админка и документы клиентов не являются вариантами. EDITOR не управляет ссылками.

Эти переадресации, CMS и консультант работают на Node-сервере. На GitHub Pages их нет; этот адрес используется только для просмотра опубликованного дизайна и содержания. Для обновления снимка — PREVIEW.md.

## Редакционные обновления без reset

`npm run content:review` показывает план; `npm run content:review -- --apply-drafts` — отдельное явное действие только в development. Оно создаёт отсутствующие страницы/ответы и дополняет незаполненные поля черновиков. Не запускается при старте, не заменяет заполненные значения или существующий черновик владельца и ничего не публикует. Перед любым импортом нужен backup. Основной `seed:dev` не использовался для этой доработки; install/start больше не вызывают seed автоматически.


Служебная запись знаний с ключом `contacts` берёт факты из опубликованных «Сайта и контактов». Публикация телефона, почты, географии или режима синхронно обновляет её; черновик не меняет ответ. Не копируйте контактные значения в другие FAQ и не редактируйте эту запись вручную в обход общего источника. После удаления всех контактных сведений материал снимается с публикации; повторное одобрение выполняет ADMIN. При снятии публичных настроек сайта с публикации консультант и отправка формы закрываются, а посетитель не получает черновые контакты.
