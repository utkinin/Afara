# AFARA

Текстильный дизайн и инженерная студия. Переносимое Next.js-приложение с Payload CMS и PostgreSQL. Шторы и текстиль для частных и общественных интерьеров: дома, квартиры, HoReCa, офисы, сцены, образовательные учреждения и частные яхты. Второй свет и остекление от 3 до 6 м, эркеры, многослойность, Wave, blackout, моторизация; изготовление по эскизам и размерам заказчика, сотрудничество со студиями и white label. Базируемся в Санкт-Петербурге, работаем по всей России, отправляем изделия в ОАЭ.

## Локальный запуск

Node.js 24, npm 11, Docker с Compose. В облачной среде:

```bash
cd /workspace/Afara
bash scripts/cloud-install.sh
npm run dev
```

На другом компьютере: `npm ci`; скопировать `.env.example` в `.env.local`, сгенерировать уникальный `PAYLOAD_SECRET` (`openssl rand -hex 32`), заполнить локальные параметры SMTP из примера, затем `docker compose up -d --wait`, на **пустой** БД `AFARA_STAGE=build npm run db:migrate`, затем `npm run dev`. Демоданные на новой development-базе создаются отдельно явной командой `npm run seed:dev`; для существующей базы seed не нужен. В development почта доставляется только в локальный Mailpit, не внешнему получателю. База доступна только через loopback и не предназначена для production.

Первый владелец создаётся **приватно в терминале**: `npm run create:admin`. Команда запрашивает email и скрытый пароль, отказывается создавать второго владельца. Общего логина/пароля нет. После этого открыть маршрут `/admin` своего запущенного приложения. Публичный first-register заблокирован.

Основной сайт — `/`; в сохранённой CMS опубликованы 20 страниц: главная, два обзора, 14 направлений, контакты, «Партнёрам» и «Пошив по эскизам». Полную структуру, включая частные яхты, подтвердил владелец. При отсутствии юридических документов форма честно блокирует реальную отправку. Контакты по просьбе владельца пусты. Изображения — визуальные концепции с общим пояснением, временные до загрузки исходников владельца. Существующие данные сохраняются. Автоматического seed при установке/старте нет; ручной development-seed отказывается перезаписывать базу и запрещён в production.

Worker запускается отдельным процессом: `npm run worker`. Заявка и задание уведомления хранятся одной строкой в PostgreSQL; отсутствие worker не теряет данные. В облаке Mailpit API используется тестами по loopback, публичного почтового сервиса ещё нет.

## Проверки

```bash
npm run typecheck
npm run lint
npm run build
npm run start
# Интеграционные тесты: только отдельная БД с именем *_acceptance
# и отдельная копия media, сервер должен использовать те же параметры:
DATABASE_URL=postgresql://postgres@127.0.0.1:5432/afara_content_acceptance MEDIA_DIR=/workspace/afara-acceptance-media npm test
npm run test:e2e
```

Интеграционные тесты проверяют `AFARA_STAGE=development` и суффикс `_acceptance` имени БД. Копия должна быть **изолированной, без реальных обращений**, с отдельным каталогом media: временно создают синтетические документы, пользователей и обращение, затем удаляют их. Не направлять тесты на рабочую среду. Chromium в облачной машине: `/usr/bin/chromium`; на другом компьютере изменить `PLAYWRIGHT_CHROMIUM_EXECUTABLE` либо установить браузер Playwright. Скриншоты в `docs/screenshots`. Не запускать build и dev одновременно в одной `.next` и перезапускать сервер после изменения зависимостей.

## Структура

- `src/app/(frontend)` — серверные страницы, форма, узкие API заявок/экспорта/readiness/консультанта и 302 коротких ссылок.
- `src/app/(payload)` — штатные маршруты Payload, одна админка.
- `src/payload.config.ts`, `src/cms` — коллекции, роли, версии, загрузки.
- `src/lib/notifications.ts`, `scripts/worker.ts` — постоянная очередь SMTP с атомарным lease.
- `src/migrations` — шесть последовательных проверенных миграций, включая новые коллекции.
- `compose.yaml` — только development; `compose.production.yaml`, `Dockerfile` — переносимое размещение.

## Консультант и ссылки

Консультант использует только одобренную опубликованную базу знаний CMS, прикладывает внутренние ссылки и отказывается выдумывать неизвестное. Сейчас доступны 74 публичных материала и поиск с буквальными цитатами; девять прежних FAQ проверены и опубликованы по указанию владельца 18.10.2026. Настоящая модель требует серверного ключа, отдельного включения и решения о передаче сообщений провайдеру. Без ключа поиск не имитирует генерацию. Настройки и проверенные ограничения — DEPLOYMENT.md.

ADMIN управляет `Короткими ссылками`: имя `/s/yahta`, опубликованная цель, включение/отключение, копирование/Share. Ссылка живёт в PostgreSQL, делает 302 и не ведёт на произвольные внешние сайты. На статическом github.io этого маршрута нет.

Редакционный план из новых вложений — `content/`, отдельная команда `npm run content:review` (без записи) или явное `-- --apply-drafts`. Она не публикует и не перезаписывает заполненные поля/черновики владельца. Не используется в install/start. Реальные кейсы и специалист заполняются только после получения подтверждённых материалов.

## Расширение содержания и услуг

Позиционирование, ОАЭ, партнёрство и пошив: [принятые решения](docs/CONTENT_DECISIONS_2026-10-16.md), [семантическая карта](docs/SEMANTICS_AFARA.md), [проверки обновления](docs/services-validation-2026-10-16.md). `content:expand` требует приватный исходный снимок CMS (`AFARA_EXPANSION_BASELINE`) и по умолчанию показывает план; явный `-- --apply` публикует согласованное обновление в транзакции.
