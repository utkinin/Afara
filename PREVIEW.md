## Повторное обновление

1. Запустить сервер на опубликованной CMS, без seed/reset. После переноса на хостинг источником становится фактическая серверная CMS; старый облачный dump поверх неё не восстанавливать.
2. Экспортировать в новую пустую папку: `PREVIEW_OUTPUT=/путь/к/новой/папке/Afara npm run preview:build`. По умолчанию источник — порт 3000, префикс — `/Afara`. Генератор отказывается перезаписывать непустой каталог.
3. Сохранить прежние downloads и добавить новые публичные инструкции. Приватные backup/секреты не копировать. Записать `deployment.json` с исходным commit и фактическими счётчиками.
4. Проверить статическим сервером с корнем выше Afara: `PREVIEW_TEST_ORIGIN=http://localhost:порт npm run test:preview`; затем `MATERIAL_STUDY_TEST_ORIGIN=http://localhost:порт node --test tests/material-study.acceptance.mjs` и `PREVIEW_TEST_ORIGIN=http://localhost:порт node --test tests/care-preview.acceptance.mjs`.
5. Опубликовать содержимое Afara обычным push в gh-pages с сохранением истории, без force и переключения основного checkout. После успешного Pages workflow проверить внешний HTTPS, обычный URL без query, HTML, изображения, скрипты и архивы.

Экспорт читает только анонимный HTML и публичные медиа. Приватные API, гидратация и скрипты приложения исключены. Маленькие контроллеры обеспечивают меню, шаги формы, выбор задачи и просмотр ткани без отправок. Скрипты и ленивый импорт имеют cache keys по содержимому. CSP запрещает connect-src и form-action. Шрифты локальные, лицензии в licenses/.

Прежний `/partnyoram/` — HTML-переход к `/partneram/`, не 302. Снятая с публикации цель не попадает в новый экспорт.
