## Обновление

1. Запустить основное приложение с согласованным опубликованным содержимым и `AFARA_DB_PUSH=false`.
2. Экспортировать в новую пустую папку: `PREVIEW_OUTPUT=/путь/к/новой/папке/Afara npm run preview:build`. По умолчанию источник — порт 3000, префикс — `/Afara`. Генератор отказывается перезаписывать непустой каталог.
3. Сохранить прежние downloads в новом снимке. Архивы v1/v2 остаются историческими, не выдаются за текущую CMS/новый выпуск.
4. Проверить статическим сервером с корнем выше Afara: `PREVIEW_TEST_ORIGIN=http://localhost:порт npm run test:preview`; затем `MATERIAL_STUDY_TEST_ORIGIN=http://localhost:порт node --test tests/material-study.acceptance.mjs`.
5. Публиковать содержимое Afara обычным push в gh-pages с сохранением истории, без force и переключения основного checkout. После успешного Pages проверить внешний HTTPS, HTML и ресурсы.

Экспорт читает только анонимный HTML и публичные медиа. Приватные API, гидратация и скрипты приложения исключены. Отдельные маленькие контроллеры обеспечивают меню, шаги формы, выбор задачи и просмотр ткани без отправок. Скрипты и ленивый импорт получают cache keys по содержимому. CSP запрещает connect-src и form-action. Шрифты локальные, лицензии в licenses/.

Прежний `/partnyoram/` — HTML-переход к `/partneram/`, не 302. Снятая с публикации цель не попадает в новый экспорт. Старые архивы и история ветки сохранены.
