Статус и исходники новой доработки отмечены отдельно в `deployment.json` опубликованного снимка.

Сохраняются 20 страниц прежней публикации основной CMS: главная, обзоры и направления, контакты, «Партнёрам» и «Пошив по эскизам». Новый блок добавлен в статический просмотр главной и «Пошива по эскизам». Сохраняются позиционирование, география по России и отправка в ОАЭ, пять FAQ прежней партнёрской страницы и старый адрес `/partnyoram/` — как статический HTML-переход к `/partneram/`. Это не серверная переадресация 302.

GitHub Pages — отдельная статическая версия для проверки дизайна и текстов. Меню, внутренние ссылки и оба шага формы работают; ввод сохраняется при возврате. Консультант, отправка заявок, CMS, черновики, административные API и серверные короткие ссылки здесь отсутствуют. Изображения — визуальные концепции с общим пояснением, без утверждения о выполненных проектах. Превью закрыто от индексации. Шрифты локальные, лицензии в `licenses/`.

## Обновление

1. Запустить основное приложение с опубликованным согласованным содержимым.
2. Выбрать **новую пустую** папку вне checkout: `PREVIEW_OUTPUT=/путь/к/новой/папке/Afara npm run preview:build`. Источник по умолчанию — локальный порт 3000, префикс — `/Afara`; доступны PREVIEW_ORIGIN/PREVIEW_BASE.
3. Сохранить предыдущие публичные downloads в новом снимке. Архивы v1/v2 относятся к предыдущему редакционному пакету; свежие страницы не выдают их за новый архив.
4. Поднять статический сервер с корнем на уровень выше Afara. Выполнить `PREVIEW_TEST_ORIGIN=http://localhost:порт npm run test:preview`: переходы, загрузка ресурсов, меню, форма, сохранение идей, прежний партнёрский адрес и 404 служебных маршрутов.
5. Публиковать содержимое Afara обычным push в gh-pages с сохранением истории, без force и переключения основного checkout. Проверить завершение GitHub Pages и внешние HTTP-ответы с новым параметром версии.

Генератор читает только анонимный HTML и публичные обработанные медиа/статические ресурсы. Скрипты приложения и данные гидратации исключены; маленький отдельный скрипт обеспечивает меню и форму. CSP запрещает connect-src и form-action. Непустой каталог экспорта не перезаписывается.
