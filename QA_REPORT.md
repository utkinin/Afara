# AFARA: локальная приёмка 15.10.2026

Это первая рабочая реализация, не разрешение на публичный запуск. Подтверждённые результаты ниже относятся к изолированной облачной машине и синтетическим данным, не к ещё не выбранному production-хостингу.

## Проверено

- Node 24.19.0, npm 11.9, Next 16.4.1, Payload 3.90.2, PostgreSQL 17. Совместимость peer dependencies проверена до установки. Каркас сверён с официальным Payload blank template; CSP/proxy — с документацией установленного Next.
- Повторный `scripts/cloud-install.sh`: `npm ci` из lockfile, восстановление Docker-сервисов, генерация типов/import map, повторный seed без перезаписи 7 существующих страниц.
- `npm run lint`, `npm run typecheck`, production build — прошли без подавления ошибок. `npm run start` использует standalone server, копирует статические файлы и сохраняет абсолютный путь постоянного media. Readiness отвечает по реальной PostgreSQL.
- `npm test`: 2 теста (валидация/CSV и большой сквозной сценарий PostgreSQL + браузер + SMTP). `npm run test:e2e`: 2 теста публичного сайта и анонимных ACL. Все 4 теста прошли на production-сборке; отдельный тест реального worker добавлен и также прошёл.
- ADMIN/EDITOR: запрет чтения заявок, повышения роли и публикации для EDITOR; прямое изменение опубликованной записи без draft отклоняется. Новый черновик не виден анонимно, правка не меняет опубликованный H1, авторизованный preview показывает новый текст.
- Изображение-черновик по прямому URL — 403. Повреждённый PNG отклонён. JPEG/PNG/WebP обрабатываются и перекодируются; EXIF отсутствует у проверенных восстановленных производных. Source/основание прав закрыты от анонимного чтения.
- Настоящая двухшаговая форма: переход, сохранение при возврате, сетевой сбой и повтор, успех только после записи БД. Повтор одного ключа — одна заявка, изменённое содержимое с тем же ключом — 409, попытка присвоить статус — 400. В production-наполнении нет фиктивных юридических документов: без опубликованных privacy/consent отправка выключена.
- Mailpit реально получил SMTP-письмо. Проверены два параллельных claim, сбой SMTP с сохранением заявки и назначением повтора. Отдельный процесс worker доставил задачу, штатно завершился по SIGTERM; новый процесс восстановил просроченный lease. Во время проверки исправлено удержание процесса внутренними таймерами Payload после shutdown.
- Через настоящую мобильную админку сохранён черновой H1 и проверен preview. Сняты медиабиблиотека и журнал заявок на 390/1440. Архивирование работает; CSV endpoint закрыт для анонимного доступа и нейтрализует начальные формулы.
- При смене пути опубликованной страницы старый адрес даёт постоянный HTTP 308 на текущий адрес. Алиасы ссылаются на ID, не формируют цепочку. Зарезервированные/занятые адреса отклоняются.
- Публичные проверки: 320/360/390/768/1024/1440 px, нет горизонтального переполнения; hero CTA видна на 360x640/390x844; один H1, существующие обзоры/направления, 404 неизвестного адреса. Escape закрывает dialog и возвращает фокус. На проверенных страницах нет JS pageerror.
- Production gate отдельно проверен на локальном процессе с AFARA_STAGE=production: поддельный JWT получает 403 на admin/login/leads/preview. Это проверка fail-closed, **не подключённой MFA-политики**. CSP nonce различается между ответами, unsafe-eval отсутствует, приватные ответы no-store. В браузерных JS-файлах не найден текущий PAYLOAD_SECRET.
- Обе штатные миграции применены к изначально пустой `afara_migration_check`, повторное применение не вносит изменений. Не подменяются schema push.
- Локальный pg_dump восстановлен в отдельную `afara_restore_check`: проверены H1 главной, история (10 версий) и медиа. База и архив media зашифрованы AES-256/PBKDF2, расшифровка сверена побайтно; восстановленные 39 WebP (включая синтетические артефакты тестов) декодируются без EXIF. **Не выполнен полный production drill с реальными доступами/заявками/внешним хранилищем.**
- `npm audit --omit=dev`: 0 Critical, 0 High, 0 Low, 5 Moderate по цепочке tooling esbuild/drizzle-kit. Уязвимый esbuild serve API не используется. Исправленные overrides Sharp/Nodemailer/Undici/DOMPurify/Sass зафиксированы в lockfile и проверены сборкой/функциональными тестами. Это не замена полному независимому аудиту.

## Измерения и ограничения

Один локальный Chromium, 390x844, без throttle: LCP 628 ms, CLS 0.0028, TTFB 333 ms, первоначально загружено около 586 KB сжатого JS и 19 KB изображений. Это лабораторный одиночный замер, не реальные Core Web Vitals и не INP. Публичный bundle пока подтягивает часть общего CMS UI: бюджет JS не достигнут; разделение bundles требуется до запуска. Lighthouse/slow 4G/реальные iOS Safari и Android Chrome не проверены.

Реальные фото/логотип/реквизиты не переданы; все иллюстрации — явно подписанные AI-концепции. Контакты пусты по поручению владельца. SMTP в интернете, реальные MFA/recovery, домен/HTTPS/HSTS, WAF, production БД и постоянное хранилище, внешний зашифрованный backup и полное восстановление, согласованные сроки хранения/удаление заявок, все истории восстановления/конкурентные правки ещё требуют приёмки. Опциональные AI-помощники не реализованы и не имитируются.

Docker-образ `afara:local` успешно собран и запущен как непривилегированный node. Проверены readiness с PostgreSQL, настоящий HTML главной и 403 административного входа без MFA. Первоначальная online-установка остановилась из-за `getaddrinfo EAI_AGAIN proxy` внутри BuildKit; успешная сборка использовала проверенный npm-кеш (`NPM_CONFIG_OFFLINE=true`), без отключения TLS/проверки integrity. Сборка внутри образа — Node 24.22.0, та же зафиксированная прикладная зависимость. Сайт остаётся доступен только для локальной проверки, публичного деплоя нет.

Повторяемые install_script и start_skill сохранены в черновик конфигурации облачной среды. Само сохранение не публикует среду и не размещает сайт. Новая задача после публикации снимка отдельно не проверялась.
