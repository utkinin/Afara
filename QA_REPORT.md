# AFARA — отчёт о доработке, 15.10.2026

Результаты относятся к облачной development-машине, production-сборке приложения и изолированным тестовым данным. Статический GitHub Pages и серверное приложение проверяются отдельно. Это не независимый аудит и не заявление о готовности принимать реальные заказы.

## Реализовано

- Дизайн, Cormorant Garamond/Manrope и палитра сохранены. Типографика увеличена по последнему указанию: H1 42–48/72–88 px, H2 36/48–60, карточки 27/32, текст 18/20, интерфейс 17–18, подписи 15–16. Большие serif-заголовки weight 500, текст line-height 1.6. Hero свободно растёт. Стрелки — SVG, без отсутствующего символа шрифта.
- Опубликованы 18 страниц: главная, два обзора, восемь частных и пять общественных направлений, отдельные частные яхты и контакты. Все направления подтверждены владельцем в переписке. Новые страницы содержат собственные задачи, согласования, факторы расчёта и публичные ответы; добавление направления выполняется через CMS.
- На главной добавлены объяснения, подтверждённая специализация студии, состав работы, согласования, стоимость и шесть FAQ. Телефон, почта, мессенджеры, часы и реквизиты остаются пустыми по поручению владельца; география — весь мир, российское отделение Санкт-Петербург. Контакты имеют один источник и ссылки в header/mobile/footer.
- Подготовлены поля имени/роли/портрета специалиста и коллекция реальных кейсов «задача → пространство → решение → фото». Человека, работы, отзывы и сертификаты не выдумывали. Пустая галерея не выводится; ИИ-концепции не принимаются за фотографии кейса. Существующие концепции честно подписаны.
- База знаний: 21 одобренный опубликованный материал (14 услуг, 6 FAQ, география), ещё 9 редакционных ответов — черновики. Виджет загружает панель после открытия и обращается к серверу только после отправки вопроса.
- Поиск PostgreSQL FTS/GIN, проверка публикации и approval, ссылки на точный текст, запрет произвольного вывода модели, повторная проверка источника после ответа, консервативный отказ при противоречиях одной темы. Нет источников из заявок, личной библиотеки, внутренних файлов и черновиков. Контакты не создают заявку автоматически.
- Адаптер OpenAI Responses API со strict JSON, `store:false`, тайм-аутом и квотами. **Без ключа сейчас работает явно обозначенный поиск с цитатами, не генерация ИИ.** Платные запросы не выполнялись.
- «Короткие ссылки» ADMIN: сохранение в PostgreSQL, выбор публичной страницы, копирование/Share, изменение/отключение, 302/no-store. Внешние цели, админка и документы клиентов не допускаются. Удалённая или снятая с публикации цель даёт 404.

## Сохранность CMS

Перед изменением схемы сохранены БД и media вне checkout. Seed существующей CMS не запускался; на отдельной пустой CI-базе development-fixture создаётся явно. Install/start больше не вызывают его автоматически. Сначала создавались только новые черновики. Публикация направлений выполнена после явного подтверждения владельца.

Шесть первоначальных внутренних страниц не переписывались: проверено полное совпадение записей по SHA-256. На главной заполнены только прежде пустые пояснения, существующие заголовки, вступление, фото, CTA и карточки сохранены. Новые блоки находятся в добавленных полях сайта; старые контакты, меню и подписи формы сохранены, в список пространства добавлены новые варианты. Повторный `content:review -- --apply-drafts` оставил опубликованные страницы и настройки полностью неизменными.

Четыре последовательные миграции прошли на новой отдельной БД. Обновлённый дамп восстановлен в отдельную `afara_content_acceptance`, фотографии скопированы отдельно; интеграционные тесты работали с этой копией и отказываются запускаться против обычной/production-базы. Это проверка локального восстановления, не настроенный внешний production-backup.

## Быстродействие и границы

Дополнительная проверка production-сборки в локальном Chromium, 390×844, DPR 1, без throttle: hero 218522 байта, первоначальные изображения 237240 байт, сжатый JS 587400 байт. Панель консультанта отсутствует в первоначальных ресурсах, появляется только после открытия; ни одного запроса к консультанту до отправки вопроса. Hero теперь выбирает достаточный обработанный исходник, а не растянутую миниатюру. Это лабораторные данные передачи, не полевые Core Web Vitals.

**Бюджет первоначального JS 200 KiB пока не достигнут:** сохраняется прежнее попадание части общего CMS UI в публичный bundle. Это отдельная незавершённая оптимизация перед полноценным запуском. Старые замеры LCP/CLS в `docs/performance.json` относятся к предыдущей версии и не выдаются за результаты этой доработки. Slow 4G, INP/p75, реальные устройства и целевой хостинг не проверялись.

## Что требует реальных материалов или настроек

- Имя/роль/портрет специалиста, реальные кейсы и фотографии с правами, логотип. Сейчас нет придуманных портфолио и лица студии.
- Публичные каналы связи, часы/часовой пояс при наличии, оператор и реквизиты. Страница контактов готова, но заполнена только подтверждённой географией и описанием обращения.
- Фактические договорные условия и проверка девяти дополнительных FAQ. Гарантии, цены, графики, свойства и сертификаты конкретных материалов не генерируются.
- Юридические документы privacy/consent, включая оценку внешней передачи сообщений модели. Пока реальные заявки заблокированы; синтетические документы существовали только в изолированных тестах.
- Ключ AI-провайдера, разрешённая сеть, отдельное включение и живая приёмка модели. Нельзя обещать полное отсутствие ошибок или выявление всех противоречий между разными темами.
- Полный Node/Docker-хостинг, домен/HTTPS, настоящие MFA/recovery, SMTP и доставляемость, WAF, минимальные права БД, внешние зашифрованные backup/restore, сроки хранения и ответственный за сопровождение.

GitHub подтвердил успешную публикацию снимка `b33cce0`: [run 38746683418](https://github.com/utkinin/Afara/actions/runs/38746683418). Статический снимок размещён отдельно на https://utkinin.github.io/Afara/ и не является размещением этих серверных функций. Облачные настройки сохраняются как черновик; сохранение не применяет их и не публикует новый снимок среды. Новая задача после публикации среды отдельно не проверялась.


Дополнительно проверена сборка при намеренно недоступной БД: после переноса чтения request headers перед инициализацией CMS в защищённом preview она проходит без попытки подключения к PostgreSQL. Это не отключение ошибок БД на runtime: readiness и обработчики по-прежнему проверяют настоящую БД.

Текущий Docker-образ `afara:review-20261015` / `afara:local` успешно пересобран и запущен как uid/gid 1000 node. Через настоящий HTTP проверены readiness PostgreSQL, HTML главной, 403 admin без MFA, сохранённый 302 `/s/yahta` и публичный поиск консультанта по яхтам. Временный smoke-контейнер остановлен/удалён. В VFS-среде потребовалось освободить старый сборочный кеш; прежние AFARA-образы предварительно сохранены в проверенный локальный архив, БД и media не удалялись. TLS/integrity не отключались, сборка использовала проверенный npm-кеш.

Проверка единого источника дополнена синхронизацией опубликованных контактов с материалом консультанта `contacts`. Отдельно проверяются сохранение черновой географии без изменения ответа и закрытие сайта/консультанта при снятии глобальных настроек с публикации; публикация возвращает актуальные контакты.

CI-рецепт обновлён: отдельная *_acceptance БД, явные миграции, test-only добавления и переносимый путь Chromium. Генератор env отдельно выполнен и проверен в временном каталоге. Такой bootstrap не применяется к существующей CMS и отказывается заменять данные. Сам workflow Validate AFARA на GitHub не запускался; его команды проверяются локально на свежей отдельной БД. Публикация GitHub Pages подтверждена отдельным workflow.
