# AFARA: решение первой реализации

Основа — AFARA_Codex_Final_Prompt (1).md и приложенный эскиз. Ранний Final_Prompt — предыдущая редакция; deep.txt — исследования и примеры, не готовый код. Документы про SEO и AI дополняют требования; AI необязателен. Прямое поручение пользователя создать проект разрешает создание исходников в прежде пустом репозитории.

## Стек
Next.js 16.4.1 / React 19.2.7 / Payload 3.90.2 / официальный PostgreSQL-адаптер. Peer dependencies проверены в npm registry; каркас административных маршрутов — официальный blank template payloadcms/payload. Node 24. Никакого второго ORM и второй админки. PostgreSQL 17; постоянный закрытый локальный каталог медиа. SMTP + отдельный процесс worker. Production-подключения не приобретаются и сайт не публикуется.

## Макет
Ivory #F7F3EA, текст #2E2E2E, сливовый #4A2F3F. Заголовки Cormorant Garamond Variable, UI Manrope Variable, полная кириллица, локальные WOFF2, SIL OFL (лицензии пакетов).
Контейнер min(1320px, 100% - 2 * поле). Поля 20 / 32 / 60 px при 390 / 768 / 1440; при 320 — 16 px. Header 64 / 64 / 88 px. Кнопки от 48px; focus-visible 2px; шрифты полей 16px. Секции 56 / 72 / 96 px. Заголовки clamp; без зафиксированных переносов.

Главная: полноширинный hero → два пространства (2/2/1 колонки) → композиции (3/3/1) → разбор (3/3/1) → материалы (5:7 / stack / stack) → четыре шага → сливовый блок условий → двухшаговая форма (5:7 / stack / stack) → footer. На телефоне hero с нижним расположением текста, основная CTA до прокрутки на 360x640. Карточки прямоугольные, без тяжёлых теней. Порядок и видимость секций управляются CMS.

Навигация: desktop две группы направлений; mobile модальный dialog, Escape/возврат фокуса/недоступный фон нативного dialog. Аккордеоны групп — details. Якоря учитывают sticky header. Reduced-motion отключает плавность.

Payload: штатная русская админка, структурированные текстовые поля без произвольного HTML, черновики и версии страниц/настроек/документов; ADMIN публикует, EDITOR только редактирует черновики. Медиа не публичны до отдельного подтверждения публикации ADMIN. Preview требует сессии. Первый ADMIN создаётся через CLI, не веб-форму. MFA production требует внешнего проверенного шлюза; отсутствие подключения блокирует production.

Форма: шаг 1 объект/город/задача/необязательный бюджет; шаг 2 имя/один контакт/согласие. Back сохраняет память компонента; ошибки фокусируют поле, успех только после транзакционной записи PostgreSQL. Отдельный SMTP worker, outbox в той же записи заявки, атомарный SQL lease. Без localStorage.

## Состояния
Ссылки normal/hover/focus; кнопки disabled/loading; форма errors/pending/success/retry. Нет публичных пустых страниц. Неизвестные URL — 404. Вся разработка noindex до подтверждения оператора, документов и production-настроек. Визуальные концепции не представляются реальными работами AFARA.
