# Карта редактирования AFARA

Блок JTBD «Ваша задача»: `pages.sections[kind=details,anchor=your-task]`, штатные `heading/body/kicker/cards[].title/body/linkLabel/visible`. Одна кнопка готовит описание в существующей форме; не создаёт профиль и не отправляет заявку. Первоначальные четыре карточки — `content/customer-tasks.ts`, дальнейшая редактура — в CMS. Офлайн и презентационный смысл фиксируется в docs/SALES_CONCEPT.md и docs/PRESENTATION_BRIEF.md. Новых таблиц нет.

В базе знаний добавлено `knowledge.evidence`: служебные источники, дата проверки и ограничения; чтение только сотрудникам, не публичному API и не консультанту. `content/answer-library.ts` — 32 подготовленных ответа по существующим путям; `content:answers --apply` создаёт только отсутствующие черновики. Разметка JSON-LD строится на сервере из тех же публичных полей и одобренных ответов, без второго ручного источника текста.

Аналитика: ADMIN читает `/admin/analytics`; флаг включения — `site.analytics.enabled`. Условия — опубликованный документ `documents.kind=analytics` вместе с privacy. Служебные коллекции `analytics-visitors/sessions/events` закрыты для публичного чтения и EDITOR; контакты берутся только из `leads` через отдельное согласие. Поля `leads.analyticsVisitor/analyticsSession/analyticsConsentVersion/analyticsConsentText/analyticsConsentAt` создаёт сервер и не меняет обычный редактор. [Подробности](docs/ANALYTICS.md).

Блок «Свет · фактура · складка» использует существующую секцию `materials` с якорем `material-study`, без новых таблиц. Заголовок/введение — `heading/kicker/body`; первые три `cards` по порядку — нейтральный свет, тёплый свет, фактура. В каждой редактируются `title/body/image/imageAlt`; кнопка берёт `linkLabel` первой карточки. Порядок и `visible` действуют как у остальных секций. Служебные подписи выбора сборки, слоёв, увеличения и технические пояснения остаются в коде. Первичное добавление и редактирование описаны в [APPLY_MATERIAL_STUDY.md](docs/APPLY_MATERIAL_STUDY.md); наличие кода не означает, что данные уже применены в рабочей CMS.

| Публичные данные | Источник Payload |
|---|---|
| Название, подпись бренда | Сайт и контакты: `brand`, `tagline` |
| Телефон/email/адрес/география/часы | `site.phone/email/address/geography/hours` (единый источник для всех страниц) |
| Якорное меню | `site.menu[].label/anchor`; скрытые блоки исключаются из меню главной |
| Группы «Пространства» и дочерние ссылки | Опубликованные `pages` с `type=overview` и `parent` |
| H1, вводный текст, название меню | `pages.h1/intro/title` |
| URL и шаблон | `pages.path/type/parent`; название не меняет URL, при публикации нового пути создаётся постоянный HTTP 308 через связь на ID |
| Hero и мобильный кадр | `pages.hero/heroMobile/heroPosition` |
| Статус иллюстрации и CTA | `pages.conceptLabel/cta/detailsLabel` |
| Рубрики, заголовки и тексты секций | `pages.sections[].kicker/heading/body` |
| Порядок/видимость/якоря | Порядок `sections`, `visible`, `anchor` |
| Карточки/этапы/условия/FAQ | `sections[].cards[].title/body/image/page/linkLabel` |
| Материалы | Секция `kind=materials`, поля `heading/body/image` |
| Alt и подпись медиа | Контекстный alt: `pages.heroAlt`, `sections.imageAlt`, `sections.cards.imageAlt`; fallback `media.alt/caption`; происхождение `media.origin`, закрытый источник `source`, подтверждение `rightsConfirmed` |
| Заголовок и пояснение формы, этапы, поля, кнопки, ошибка и успех | `site.form`; объектные варианты `site.form.spaces` |
| Правовые документы | `documents.title/slug/body/kind/version`, версии/черновики |
| Footer | `site.footerText`; ссылки строятся по опубликованным документам |
| Title/description | `pages.seo`, fallback на `h1/intro` |
| Получатель уведомлений | Закрытые настройки `notifications.recipient`, только ADMIN |

Автоматически вычисляются: крошки, ссылки на родителя, canonical/sitemap, номер этапа, размеры изображений, `tel:`/`mailto:`, идентификатор и время заявки, версия опубликованного согласия. Неподтверждённые направления не выводятся.

Технические строки интерфейса пока в коде: skip-link, кнопки открытия/закрытия меню, «Согласие», «политика обработки данных», placeholder выбора объекта/бюджета, состояния загрузки/404/неопубликованной формы, метка предпросмотра. Обычный редакционный контент находится в CMS. Перевод этих служебных надписей и брендированные favicon/логотип — отдельный пункт доводки после предоставления исходников.

## Доработка содержания и серверных функций — 15.10.2026

| Данные | Источник и правила |
|---|---|
| Направления, включая частные яхты | `pages` (`direction`), `parent`, `navOrder`, `serviceConfirmed`; новое направление не требует кода. ADMIN подтверждает оказание услуги перед публикацией |
| Общая структура пространств | `overview` + дочерние опубликованные страницы; направления без родителя (яхты) — отдельные ссылки в том же меню |
| Контакты | Страница `pages.type=contacts`, путь `kontakty`; H1/введение в странице, все каналы из `site`, ссылка автоматически в header/mobile/footer |
| Мессенджеры, пояснения к встречам и реквизиты | `site.messengers`, `meeting`, `legalDetails`, `timezone`; пустые значения не выводятся |
| О студии и специалисте | `site.studio.heading/body/name/role/photo/verified`; отображение только после проверки, имя/фото не выдуманы |
| Состав работы, согласования, расчёт, FAQ | `site.trust[]` — те же готовые шаблоны и порядок, что у секций страниц |
| Реальные работы | `works.title/task/space/solution/photos/verified`; только ADMIN публикует, ИИ/концепции не принимаются как фотографии результата. Пустая галерея скрыта |
| Утверждённые ответы | `knowledge.question/answer/topic/keywords/page/approved`; черновики недоступны консультанту. Публичный ответ отображается на странице-источнике с якорем `answer-ID` |
| FAQ на главной | Шесть утверждённых записей `knowledge` главной. Если они опубликованы, дублирующий FAQ в `site.trust` скрыт; заголовок берётся из FAQ-блока |
| Виджет консультанта | `site.assistant.enabled/title/intro/placeholder`; начальная страница загружает только кнопку, панель — после открытия |
| Короткие ссылки | `short-links.slug/target/enabled`; только ADMIN, `/s/имя`, серверный 302, без произвольных внешних назначений |

Публичная база не индексирует весь CMS автоматически: ADMIN явно одобряет отдельные записи знаний, связанные с опубликованной страницей. Заявки, личная библиотека, внутренние документы, версии и черновики не являются источниками. Внутренние правила модели и технические сообщения интерфейса не редактируются как публичный материал.

При обычном SSR опубликованные изменения читаются из PostgreSQL без общего кеша и повторного деплоя. Статический GitHub Pages — отдельный снимок: его нужно пересобрать и опубликовать, изменения CMS сами туда не поступают.

Служебная тема `knowledge.topic=contacts` — синхронизируемый публичный материал: тело рассчитывается только из разрешённых контактных полей `site` и обновляется в той же операции публикации. Это не второй ручной источник телефона/географии. Новые обычные материалы создаются с другими ключами темы. Черновые публичные настройки не выводятся, API консультанта/заявок при неопубликованном site закрыты.

21 страница, 82 одобренных ответа, 47 активных медиа; все прежние FAQ проверены и опубликованы. Поле evidence остаётся служебным.
